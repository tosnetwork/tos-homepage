Configuration-governed.

TOS has no fixed maximum supply. Canonical genesis specifies 101,000 TOS: a 100,000-TOS validator-bootstrap wallet and two 500-TOS system reserves. Validator block rewards are calibrated toward approximately 10 million total TOS over roughly two years.

These are configuration and policy targets, not a hard supply cap or an automatic two-year transition. The current per-block reward continues until governance changes ConfigParam 14. The later ~2% annual target requires that separate change.

Issuance and fees
are different flows.

BLOCK REWARDS

Secure the network

Configured block rewards create TOS through finalized validator-produced blocks and flow through the elector’s reward accounting. Application work and off-chain scores cannot mint native TOS.

NETWORK FEES

Pay for execution

Transaction, storage, and message-forwarding fees price network resources. Fees move existing TOS; they are distinct from issuance and application revenue.

VALIDATOR STAKE

Participate in elections

Stake limits and recurring elections govern validator participation. Four equally weighted validators are the canonical bootstrap set, not proof of independent operator diversity.

Read the configuration.

The canonical template funds validator bootstrap and system reserves, with no designated team, investor, foundation, ecosystem, or treasury allocation. Public-network supply and balances require current chain-state verification. TOS provides no fixed yield or price guarantee.
