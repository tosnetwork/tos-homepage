Post-quantum today.
Cryptographically adaptable over time.

ML-DSA-44 is the current signature suite, not a permanent commitment to one algorithm. Validator descriptors and signatures carry an explicit algorithm ID; a stable validator identity is separate from the key ID, which binds the algorithm and public key. This design gives TOS a foundation for evolving its cryptography as standards, security evidence, and operational needs change.

01

Integrate the next suite

A new PQ signature scheme needs an admitted algorithm ID, verification support, and tested key, signature, and certificate limits. Today, only ML-DSA-44 is admitted; unknown algorithms are rejected.

02

Prepare validators

Release compatible node software, provision new signing keys, and validate the transition on testnet. Stable validator identity is separate from replaceable signing credentials; algorithm migration must preserve the protocol’s authorization rules.

03

Activate together

Coordinate a protocol upgrade so validators apply the same verification rules at the activation boundary. Adopting another PQ algorithm is a network upgrade, rather than an individual validator’s runtime preference.

Identity that survives key rotation.

CONTROLLER

Root authorization

The validator controller is a stable account identity. Root-authorized actions control key binding and rotation within the contract’s rules.

CONSENSUS

Dedicated signing keys

Consensus keys authenticate Simplex messages under a dedicated signing context. Consensus authority is distinct from unrestricted controller spending.

TRANSPORT

Separate network identity

ADNL transport identities route peer communication. A post-quantum consensus signature is not a claim that every network connection uses post-quantum cryptography.
